## App Overview

### Description 

**Tinder but food. We are creating the fundamental layout and silliness of Tinder and applying it to the aspect of the culinary world to broaden the users' horizons. Where the user is able to like and dislike an array of dishes, save their favorite ones, see the recipe to all, and refine their food taste. It all starts with one swipe.**

### App Evaluation

<!-- Evaluation of your app across the following attributes -->

- **Category:** Food and Wellness
- **Mobile:** Although this app would mostly be used at home, it being mobile allows it to be used on the go, perfect for shopping for your next meal. This ease of access makes it much easier than using a website.
- **Story:** This is an app designed for ourselves and our friends, most of us want to learn how to cook but do not know where to start. An app solely to give ideas with recipes and ingredients in one spot is great for that learning experience.
- **Market:** This app is marketed to both cooks and those learning to cook, as the ability to find new meals makes it useful to both sides of the spectrum. Cooking is also an important life skill, meaning the market is much wider than many other apps.
- **Habit:** The usage of the app is entirely dependent on their desire to make new meals and ingredients on hand, some may use it only for special events and others may use it for every meal they can. The user likely would have a period where they use it many times in one day then a break from the app if they are not cooking.
- **Scope:** Although the app is simple in nature it may be difficult to make it function at best quality as everyone in the group is new to Kotlin and android development. Even if we only do the bare minimum, it will still be interesting for the user to consume. Although we do not have a clear way to code it, I believe the concept and goals are clear enough to make up for our lack of coding skills.

## Product Spec

### 1. User Features (Required and Optional)

Required Features:

- **User will be able to scroll through different types of foods and their reciepes.**
- **The user will then be able to choose if they like a certain meal and be able to save it.**
- **The user will also be able to look at a catolog of the foods that they have saved.**

Stretch Features:

- **The user being able to search a meal that they want.**
- **Organizing the meals in a specific order (eg. alphabetically, country of origin, or types of ingredients).**

### 2. Chosen API(s)

- **https://www.themealdb.com/api.php**
  - **Display a random meal**
  - **Search meal by name**
  - **List all meals by first letter**

### 3. User Interaction

Required Feature

- **Click on food name button**
  - => **View recipe for food item, along with any other information**
- **Swipe right on screen** or **Hold right side of screen**
  - => **Save the food item to a list**
  - => **Save the food item to a skip list, to prevent seeing it again**
- **Swipe left on screen** or **Hold left side of screen**
  - => **Move onto the next food item**
  - => **Optional: Temporarily add that food item to the skip list**
- **Select favorite button**
  - => **Change screen to a list of all saved food items**
  - => **This allows for the first feature to be used on saved items**
- **Select discovery button**
  - => **Opens the main page, is used to move out of the favorite or search page**
- **Optional: Select search button**
  - => **Opens keyboard to type food name or type, resulting in an empty page of nothing is found. Otherwise it pulls up a clickable list of foods that match the search**
- **Optional: Select user button**
  - => **Opens a menu for user account**
  - => **Would have common options and maybe even filters for discovery**
